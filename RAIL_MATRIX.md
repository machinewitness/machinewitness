# RAIL → enforcement matrix

Codex finding #14: the plan claimed *"the eleven rails become executable tests"* while the test table had **no RAIL 8 row at all**, delegated RAIL 1 to a separate gate with no row, and tested a *phrase in a reference file* rather than the prohibited *behaviour*.

> 🔴 **No rail may be described as enforced until its row here is complete.** A rail with an empty `runtime test` column is documented, not enforced, and this file says so out loud rather than letting a green suite imply otherwise.

**Three columns do the work.** A *positive invariant* (what must be true. Not what must be absent), a *violating fixture* (proves the test fires), and a *runtime test* (executes the thing, asserts side effects). A row with only a grep is marked as such.

⚠️ **Why absence assertions are not enough**: finding #15. A planted literal proves the scanner recognises that literal. Synonyms, indirect phrasing, generated prose, a shell call, or plain model behaviour still violate the rail with every test green. File counts fixed the zero-byte bug; they did nothing for adequacy. So: **positive allowlists** where a capability can be enumerated, **mutation tests** with semantic evasions, and **execution against adversarial prompts** asserting observed side effects.

## How every test in `tests/rails/` is built

Three properties, implemented once in the shared harness so no single test can quietly do without one.

1. **Non-empty input, or abort.** Every scan proves its target is real before judging it, and throws rather than returning clean on an empty one. *Not found* and *nothing read* are the same output to a text search, and that is the failure that put this project's continuous integration green over a run which read **zero bytes**, in an already-pushed repository, inside the wrapper written to report that failure.
2. **A planted violating fixture, and it must fail.** A test that has never failed has never been tested. Every checker is a pure function over text or over an observed side effect, so each rail runs it twice: over the real target asserting silence, and over a planted violation asserting it fires.
3. **A mutation set, and execution where behaviour is testable.** Each row carries semantic evasions (synonyms, indirect phrasing, a name assembled at run time) and **the mutation sets deliberately include phrasings the check provably misses.** A mutation set that always passes claims a completeness a copy check cannot have, so each one fails if every entry starts being caught.

⚠️ **The planted fixtures are assembled at run time, not written as literals.** This repository bars an absolute date, an address, a phone number, an e-mail address and a docket number *from a fixture*, and the gate under test enforces that over its own test file. Written out, ten of them failed the gate on the first run. ⛔ The wrong fix was to exempt the file.

⛔ **One row is RED on purpose, and it runs the real assertion and fails.** RAIL 4, whose target does not exist. It is registered so the runner reports it under `todo` with the reason and the owning wave printed beside it. The summary line says how many rails are red instead of folding them into a pass. It carries a **trip-wire** that fails the day its target appears, so the rail is *demanded* rather than inherited. ⛔ It is not pointed at a stub: a test that passes because its target is absent is the failure mode this whole file exists to prevent.

⚠️ **Three rows were red when this file was written, and two have since been promoted**, RAIL 6's instrument, and RAIL 9's binding once its two callers began calling it. Each promotion was forced by its own trip-wire going red and demanding it, which is the arrangement working rather than a courtesy. ⛔ **Promoting a test is not resolving a question**: RAIL 6's row is still 🟡 because its doctrine is unresolved, and the row says why.

2. **Two contract amendments**: `block_c`'s aggregate totals (RAIL 3) and `plan_mode` action eligibility. Both are `skill/data/tree.yaml` changes, gated and reviewed, never silent edits.
3. **The intimate-media doctrine** (RAIL 6): the owner's, with counsel. The rail asks for an operation that does not exist; the engine's default is stricter than the rail; a default is not a resolution.
4. ✅ **The badge-number class in the gate. FIXED, and this entry used to say it was not.** It is now two context-separated rules in `ops/casefact_gate.sh`: one that fires on a badge-shaped token when a role word is on the line, one that fires on a badge-shaped bare number that is not a hex-colour length. Neither uses the colour drop, and reintroducing it there re-kills the class. **Verified in both directions**. It fires at five assembled shapes and stays quiet on a real stylesheet colour, asserted in `tests/rails/no-case-facts.test.mjs`. ⚠️ **Two other copies of `casefact_gate.sh` elsewhere on this machine still carry the dead class.** Reconciling them is a later owner-gated wave and is out of scope here; nothing in this repository depends on them.

   🔴 **And note what this entry was doing wrong, because the lesson is the general one.** It asserted a WORSE state than reality. Inert when the class fires, and *"a change to a shared tool in `ops/`, not a test adjustment"* when the change was already made and tested. The standing rule is that no file may claim a **broader** state than this register; **it binds in both directions.** A register that under-claims sends the next reader to re-fix something already fixed, or to distrust a gate that now works, and one of those wastes a session while the other quietly reduces what anybody is willing to rely on.

   ⚠️ **It has now happened three times, and the third was RAIL 10's row**. *The command-line entry point does not exist yet*, still written there after the launcher was built and the offline check began driving it. So this is a recurring shape, not one bad entry: a row is written while a thing is missing, the thing arrives, and the row is the last place anybody looks. **A row that names something as absent is a claim with an expiry date, and it has to be re-read whenever that something lands.**
5. **The lawyer review of outward-facing copy** (RAIL 7). Step three of three, never run for any jurisdiction. A green scan plus a clean checklist is two steps, and the missing one is the only one that can catch a claim being wrong rather than merely off-message.

## ⚠️ RAIL 7's copy check was blind to a whole part of speech, and what that generalises to

A proposed main line for this project read *"prepare evidence of your innocence for your
lawyer."* It was run against every automated check that could plausibly catch it. **Five
lexicons, zero hits**, on a line naming an outcome this rail bans:

| Lexicon | Where | Result |
|---|---|---|
| Outcome promise, RAIL 7 | `ops/casefact_gate.sh` class 6 | no hit, green |
| Surveillance vocabulary, RAIL 2 | `ops/casefact_gate.sh` class 5 | no hit, green |
| Outcome promise | `landing/scripts/copy-gate.mjs`, the RAIL 7 array | no hit, green |
| Prevalence in words | `tests/rails/positioning.test.mjs` | no hit |
| Gendered scoping | `tests/rails/positioning.test.mjs` | no hit |

**The cause is one sentence and it is worth carrying to any future lexicon.** Both outcome
lexicons were built from `legal/advertising_rules.md` §1's banned list. Every entry in that
list is a **verb phrase**, so both lexicons inherited its grammar and the whole class was blind
to **noun phrases**. The banned `prove your innocence` fired; the equally banned
`evidence of your innocence` did not.
**A lexicon built from a banned-phrase list can only catch the grammar of the list it was built
from.**

⚠️ Note what that sentence had to do to be writable at all, because it is the same lesson twice
over. Its first draft quoted the verb phrase with nothing in the clause marking it as forbidden,
and `tests/rails/no-outcome-promise.test.mjs` correctly reported this file as promising a result.
A marker governs the clause it sits in, not the whole line, so naming a barred phrase in order to
bar it means carrying the marker into that same clause. Then the paragraph you are reading made
the identical error one line further down, describing the fix. **The test was right twice and the
prose was wrong twice**, which is the argument for the check existing, written by the check.

This is the project's signature failure mode arriving for the third time, and again inside a
tool built to report it: a check that prints green because of what it never looked at. The
other two are §6 finding 2 and §9 row 14.

### What the hardened check now catches, and what it provably does not

Both lexicons gained the noun, adjective and clause forms plus a bare `innocen(ce|t)`
catch-all, worded the same in both files, **additions only**. Every fixture was proven to fire
by running the gate against a scratch file **outside** the repository, and the gate was then
proven to return to zero notes with the fixture removed. A pattern nobody has seen fail is not
known to work.

⛔ **Four shapes promise an outcome with no banned word in them and are recorded as NOT caught,
rather than implied away:**

```
the record will speak for you
this is how you get it sorted out
hand your lawyer what they need to end this
put this behind you
```

No pattern is added for these on purpose. Their shapes are too common in ordinary prose to
catch without a false-positive rate that gets the whole gate removed, and a removed gate
catches nothing at all. **They are what blocker 5 above exists for.** A human reads the copy;
the check is a floor under that reading, never a substitute for it.

### The 22 new notes are all denials, and not one file was exempted

Hardening moved the vocabulary note count from **33 to 55**. The specific phrase additions
matched **zero** new lines, because none of those phrases is in the tree. All 22 new notes come
from the catch-all, and every one was read: they are refusals (*"it will not prove anybody
innocent"*, *"never proof of innocence"*, *"does not sort the innocent from the guilty"*),

That is the pattern working rather than misfiring. A banned word is banned in a denial too, so
a negation still puts it on the page and still earns one human reading. ⛔ **No file was added
to `ops/policy_exempt.re` to clear a note, and `README.md` is deliberately not exempt.**
Exempting a file to quiet a class is how a class dies silently.
